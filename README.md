# deployctl

Собирает Go-приложение на машине разработчика и развёртывает его через SSH и Docker. Go и исходники на сервере не нужны.

## Начало работы

В существующем Go-модуле:

```bash
go install github.com/LittleDrongo/deployctl@latest
deployctl init
```

`init` создаёт `service.yaml`, добавляет `/.bin/` в `.gitignore` и подключает `buildcard`. В новом конфиге перечислены девять платформ: удалите или закомментируйте ненужные. Заполните `targets` для своих серверов; схема и пример — в [doc/CONFIG.md](doc/CONFIG.md). Если используется старый `deploy.yaml`, он продолжит работать, пока рядом нет `service.yaml`.

```bash
deployctl config check
deployctl build
deployctl doctor prod
deployctl up prod --dry-run
deployctl up prod
deployctl status
```

Перед `up` серверу нужны SSH-доступ по ключу, Docker без `sudo` для SSH-пользователя и базовый образ из `docker_base_image`. `doctor` проверяет окружение и подсказывает, как перенести образ на сервер без доступа к registry.

## Команды

| Команда | Действие |
| --- | --- |
| `init` | Подготовить модуль и конфиг; `--scaffold` создаёт пример `main.go`, `--makefile` — Makefile. |
| `info` | Показать версию приложения из Git. |
| `build` | Собрать платформы из конфига в `.bin`; `--platform` выбирает одну. |
| `doctor <target>` | Проверить сервер перед деплоем. |
| `up <target>` | Собрать, передать и запустить приложение. |
| `status [target]` | Показать таблицу для одного или всех targets. |
| `logs <target>` | Показать логи; `--follow` следит за новыми строками. |
| `stop`, `restart`, `remove <target>` | Управлять контейнером. |
| `release` | Создать локальный тег и отправить его, если настроен `origin`. |
| `clean` | Удалить локальный каталог `.bin`. |

`--root` указывает каталог Go-модуля, `--config` — файл конфигурации, `--dry-run` показывает план. Без `--root` ищется ближайший `go.mod`. Для сборки существующего тега используйте `build --tag v1.0.0` или `up prod --tag v1.0.0`. После успешного `up` локальный бинарник удаляется; `--keep-artifact` оставляет его в `.bin`.

При ошибке запуска `up` выводит состояние и последние строки логов, затем восстанавливает прежний контейнер и бинарник. Без Docker healthcheck проверяется стабильность процесса, а не готовность приложения. `status` показывает недоступный target как ошибку и продолжает проверять остальные.

По умолчанию контейнер работает с UID/GID SSH-пользователя (`container_user: ssh`), чтобы новые файлы в смонтированных каталогах можно было редактировать без `sudo`. Существующие файлы, принадлежащие root, автоматически не меняются. Серверный бинарник остаётся в смонтированном каталоге: Docker-образ содержит среду, но не сам бинарник.

## Автодополнение Bash

```bash
deployctl completion install bash
source "${XDG_DATA_HOME:-$HOME/.local/share}/bash-completion/completions/deployctl"
```

Установка через `go install` не настраивает shell. Если `bash-completion` подключён, в новых сеансах установленный файл загружается автоматически. Для CI фиксируйте проверенный тег deployctl вместо `@latest`.
